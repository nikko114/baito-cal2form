# baito-cal2form 計画書

- 状態: MVP 実装済み（§7）。実機（iPhone）での確認待ち
- 最終更新: 2026-10-17

カレンダーでシフト希望を入力すると、Googleフォームに書き写すための一覧ができるスマホ向けWebアプリ。

## 1. 目的

- シフト提出のGoogleフォームは「1日ごとにプルダウンで選ぶ」形式。質問タイトルに曜日が書かれていないので、日付と曜日・自分の予定の対応がつかみにくく、選び間違えやすい。
- 曜日の見えるカレンダーの上で希望を決め、フォームと同じ文言で1日1行の一覧を作る。フォームへの入力は、一覧を上から順に見ながら選ぶだけにする。

## 2. 前提（実際のフォームの形）

- 毎月新しいフォームが配られる（タイトル「シフト提出◯月」、締切は前月20日）。
- 日付の質問は「◯日の出勤」（1日〜月末）。曜日は書かれていない。ときどき「※極力出勤して下さい。」がつく（気にしなくてよい）。
- 「29〜31日は存在する月の時だけ選んでください」という注意書きがある。
- プルダウンは1日に1つ。選択肢は全日共通: `○` / `×` / `早` / `中` / `遅` / `9-` / `17-` / `17:30-` / `18-`。
  - ○ = 早・中・遅どれでもOK、× = 休み希望（出勤不可）、早 = 早番 8-17、遅 = 遅番 16-25、中 = 中番（時間は未確認）。
- 日付以外の質問: 社員番号、氏名、職位、備考欄。
  - 運用は「出勤できる日は全部入れて、その中から何日出勤したいかを備考欄に書く」。
- 送信後の完了ページを保存するよう指示がある（「回答を編集する」から直せるため）。
- 使う端末は iPhone。フォームの入力も iPhone でする。

## 3. 決めたこと

| 項目 | 決定 |
| --- | --- |
| 技術 | 素の HTML + CSS + JavaScript（ES Modules）。ビルドなし、外部ライブラリなし |
| 公開 | GitHub Pages（main ブランチのルートをそのまま公開） |
| 保存 | localStorage（端末の中だけ。サーバーなし） |
| 単位 | 1か月単位（フォームが月ごとなので、期間指定はなし） |
| 一覧の日付の書き方 | 初期値は `1日(日)`。`11/1(日)`、`11月1日(日)` に切り替え可 |
| 曜日パターン | MVP に入れる（毎週決まっている曜日を設定し、空いている日をまとめて埋める） |
| 未入力の日 | 赤く警告する（自動で埋めるのは曜日パターンで行う） |
| 週の始まり | 日曜（設定で月曜に変更可） |
| 開発の流れ | main に直接 push。PR は作らない |

## 4. 画面と機能（MVP）

画面下のタブで3つの画面を切り替える: **カレンダー / 一覧 / 設定**。開いたときは来月を表示する。

### 4.1 カレンダー

- 1か月表示。各日のマスに選んだ選択肢を色つきで出す。土日は色を変える。
- **タップで選ぶ**: 日付をタップすると下に選択肢のパネルが出る。選ぶと保存して自動で翌日へ進む（月末まで行くと閉じる）。パネルには選択肢ごとの説明（例: 早番 8-17）も出す。
- **塗る**: パレットで選択肢を選び、日付をタップして塗る。同じ選択肢の日をもう一度タップすると空に戻す。曜日の見出しをタップすると、その月の同じ曜日をまとめて塗る。
- **曜日パターンで埋める**: 設定した曜日パターンで、その月の空いている日だけを埋める。
- **元に戻す**: 入力の変更を1つずつ取り消せる。
- 入力済みの日数、未入力の日数、出勤できる日数を表示する。
- PC で使うとき用に、← → で日を移動、1〜9 で選択肢を選択、Esc でパネルを閉じる。

### 4.2 一覧

- その月の全日を1日1行で表示する（例: `1日(日) ○`）。週の区切りに隙間を入れる。
- 未入力の日は赤く表示する。「◯日から入れる」でカレンダーのその日に飛べる。
- 出勤できる日数（休み扱いの選択肢以外が入っている日）と、選択肢ごとの日数を表示する。
- その月に31日がないときは「フォームに31日の質問があっても選ばない」と注意を出す。
- **チェックリスト**: フォームに入れたら行をタップして ✓。進み具合（3/30 など）を出し、状態は保存する。アプリに戻ってきたとき、次に入れる行が画面外ならそこまでスクロールする。
- **一覧をコピー**（プレーンテキスト）。
- **備考欄の下書き**: 月ごとに保存。コピーボタンつき。
- **送信後の「回答を編集」リンク**: 月ごとに貼っておけて、あとで開ける。

### 4.3 設定

- 選択肢の追加・編集・削除・並べ替え（↑↓）、まとめて追加（1行1項目）。
  - フォームの選択肢の文字（一覧に出す。一字一句そろえる）、説明、カレンダー用の短い表示（任意）、色、休み扱い。
  - 使っている日がある選択肢を消すときは日数を出して確認し、その日は未入力に戻す。
- 曜日パターン（曜日ごとに選択肢か「なし」）。
- 週の始まり、一覧の日付の書き方。
- ホーム画面への追加のしかた（iPhone）。
- バックアップ: 書き出し（コピー / ファイル保存）と読み込み。
- 全データ削除。

## 5. データ設計

localStorage のキー `baito-cal2form` に、JSON をまとめて保存する。

```js
{
  version: 1,
  options: [{ id, label, short, note, color, off }], // 並び順 = フォームの順番。off = 休み扱い
  entries: { '2026-11-01': '<option id>' },          // 日付 → 選択肢
  pattern: [null, '<option id>', ...],               // 曜日パターン（0 = 日曜）
  months: { '2026-11': { checked: { 1: true }, memo: '', editUrl: '' } },
  settings: { weekStartsOn: 0, dateFormat: 'D日(W)', hideInstallTip: false },
}
```

- 日付は Date オブジェクトではなく `"YYYY-MM-DD"`（端末のローカル日付）の文字列で持つ。`toISOString()` は UTC なので使わない。
- 日付からは選択肢を id で参照する。選択肢の文字を直すと、入力済みの日にもそのまま反映される。
- 読み込み時に形式をチェックし、おかしな値は捨てる。保存データが壊れていたら別のキーに退避して最初の状態で開く。

## 8. MVP のあとの候補

- 祝日の表示
- 曜日によって選べる選択肢を変える（平日と土日で選択肢が違うフォームが来たとき用）
- 複数のバイト先（設定のセットを切り替える）
- オフライン対応（Service Worker）
- 一覧に、フォームでの並び順（何番目の選択肢か）を出す

### 発展案: 事前入力URLで「ポチポチ」自体をなくす（保留）

Googleフォームには、URL で回答を先に入れておく仕組み（`viewform?usp=pp_url&entry.<質問ID>=<値>`）がある。各日付の質問IDがわかれば、全日分を選んだ状態でフォームを開けて、確認して送信するだけになる。

- 質問IDは、フォームのページに埋め込まれた質問データ（`FB_PUBLIC_LOAD_DATA_`）から取り出せる。アプリから直接フォームを読みに行くのは CORS の制限でできない。
- フォームが毎月新しく、入力も iPhone なので、やるならフォームのページで動かすブックマークレットか、iOS のショートカット経由になる。
- 心配な点: Googleフォームの制限（CSP）でブックマークレットが動かない可能性、ログインが必要なフォームでの動き、埋め込みデータの形式が非公開で変わりうること。
- 実物のフォームで試してから入れるか決める。

## 9. 注意点・リスク

- **iPhone の Safari ではデータが消えることがある**: Safari は、しばらく操作していないサイトの保存データを消す（Safari を使った日で数えて7日。ITP）。月1回しか開かない使い方だと消えるおそれがある。
  - 対策1: ホーム画面に追加して使う（ホーム画面のWebアプリはこの削除の対象外）。アプリ内で案内を出している。
  - 対策2: バックアップの書き出し。
  - Safari とホーム画面版は保存場所が別。Safari で入れたデータはホーム画面版に引き継がれないので、移すときはバックアップを使う。
- **スマホ表示の細かい落とし穴**: `100vh` 問題（`100dvh` を使う）、ホームバーとの重なり（safe-area）、16px 未満の入力欄での自動ズーム、ダブルタップでのズーム（`touch-action: manipulation`）に対応済み。

## 10. やらないこと

- サーバー、アカウント、端末間の同期
- 確定したシフトの管理、給料の計算
- Googleカレンダーなど外部カレンダーとの連携
- フォームの自動送信（送信ボタンは必ず自分で押す）
